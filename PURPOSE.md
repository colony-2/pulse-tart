# Pulse Tart provider

This cell owns an independently packaged Pulse instance-provider plugin using https://github.com/openai/tart to execute supplied worker processes in isolated disposable VMs on operator-managed Apple Silicon macOS hosts. Its canonical repository is https://github.com/colony-2/pulse-tart.git.

Own Tart provisioning, approved template/image mapping, guest process transport, native resource admission, active managed-instance listing, restart reconciliation, lifecycle and cleanup, packaging, documentation, and macOS integration tests. Preserve worker argv, literal environment, working directory, finite stdin, and supplied-lease bytes without shell interpolation or secret logging. Reserve resources before side effects, coordinate ownership across plugin generations, and never delete unrelated VMs. Unsupported image, resource, process, deadline, or infrastructure-timeout requirements must be declined before launch.

Use only Pulse's public provider SDK once agreed and available; its SDK remains proposed in the inspected Pulse checkout. Do not copy private protocol definitions or import Pulse internals. Pulse owns placement, lease acquisition, provider protocol, and host supervision; c2j owns worker execution and lease renewal; JobDB owns durable job state. This cell does not own a scheduler, remote Mac fleet management, or Linux hosting of the local plugin.

Preserve Pulse per-item submission outcomes and original correlation metadata. Any uncertain submission after a start may have occurred remains unknown, with no replay or fallback. Listing is observational and includes only active owned instances with exact launch filters and pagination; it never authorizes resubmission. Accepted workloads must survive plugin/controller disconnection under supervised lifecycle and infrastructure limits, with eventual owned-resource cleanup.

Use Tart's verified Functional Source License 1.1 with Apache-2.0 future license (FSL-1.1-ALv2), including its two-year future grant, for this project's implementation with appropriate new-work attribution and release dates. Retain upstream notices for copied material. Do not describe current releases as immediately Apache-2.0 or MIT. Pin and recheck the actual Tart release and its license before implementation; the consultation inspected upstream main on 2026-11-01.

Follow-on implementation must validate strict configuration, version/help and Pulse check without VM launches, SDK compatibility, process and lease delivery, concurrent admission and listing, partial batches, uncertain starts, deadline enforcement, restart reconciliation, and cleanup ownership. Require deterministic command fixtures, SDK conformance and subprocess tests, and gated real Apple Silicon macOS tests that boot an approved VM, run a supplied-lease worker, list it, finish it, and verify cleanup. Crash tests must prove workload survival and infrastructure limits. Validate supported guest operating systems explicitly.

Creation establishes these responsibilities only. It does not deliver the backend or make Pulse's proposed SDK available. Preserve the original full feature request and consultation design for a subsequent implementation consultation, including selection and validation of guest transport and durable VM supervision.
