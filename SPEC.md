# macOS cell provider

Implement `github.com/colony-2/pulse-provider-api.Provider` as an importable Go library with Orchard and direct Tart backends. No provider CLI, plugin framework, YAML loading, or independent supervisor. Scope is macOS ARM64 concurrency slots; Linux guests and shared volumes are deferred.

**Configuration and ownership.** Both constructors take the same typed `Config` for bases, slot groups, state, and bootstrap. Orchard adds connectivity and worker placement; Tart adds executable/home and SSH/command timeouts. Copy mutable inputs. Default slot size is 4 vCPU / 8192 MiB; count zero drains. One runtime locks each private durable state directory. One host owns each backend/owner scope. Constructors create no VMs; the host explicitly drives reconciliation.

**Bases.** Catalog entries declare a concrete name, digest-pinned OCI image, actual macOS version, SSH access, and capabilities. `DefaultBases()` supplies digest-pinned `macos-26-arm64` (Tahoe 26.6.2), then `macos-15-arm64` (Sequoia 15.7.7), with independent mutable values. Callers explicitly assign slot counts; the catalog creates no VMs. Verify the exact configured OS version regardless of the major-version base label. Selectors match concrete names case-sensitively; each `*` anywhere matches zero or more characters, including `/`, with all other characters literal. Labels are valid UTF-8, 1–4096 bytes, without NUL, spaces, tabs, CR or LF; concrete names cannot contain `*`. There are no aliases. `GetCapabilities` returns the complete configured catalog and capability sets in `Config.Bases` preference order, independent of slot occupancy/readiness/count. Return copied data without secrets or backend calls; honor cancellation and closed runtimes. Admission prefers the first fitting available base in that order, then the smallest fitting slot. Capabilities use exact all-of set semantics. Verify OS version and configured built-in tool capabilities inside each template before readiness.

**Prepared images.** Reconciliation adopts named local sources or prepares missing ones. Install Nix/c2j/tools once into a shared stopped base, then independently clone, configure and boot a template per slot. Resolve `Config.C2JVersion` (`latest` by default, or a tag/commit) only for missing base installation. No c2j version is compiled into the library; existing images survive library/version-selector changes. The setup archive is internal, with no public bundle configuration. No release manifest or installed-version sidecar; inspect `c2j version`.

**Independent updates.** A standalone local Tart script uses the same guest preparation scripts to build a base and every requested suspended template before publication. Stable names identify owner/base/group/size/slot, not c2j version. Give replacements fresh MACs. Publish canonical names and matching Orchard worker-local aliases using `tart clone --overwrite`; no Pulse RPC. Serialize each replacement with Tart cloning, without promising a pool-wide transaction. Existing ordinary clones retain their environment; subsequent clones use replacements. Keep old sources if preparation fails. Remote Orchard fleet updates are deferred.

**Slots.** Verify an unused guest with no lease, execution intent, or worker service. Capture boot UUID and MAC; reject duplicate template MACs. Suspend only after readiness. Persist template identity, configuration fingerprint, phase and worker. Jobs clone the untouched suspended source on the same host, preserving all saved hardware. A boot UUID/MAC guard reads the readiness identity inside the clone and rejects cold-boot fallback before lease delivery; do not compare against a host-cached identity from a replaced template. One unresolved/active clone reserves its slot; different slots use different MACs. No queue: warming/busy slots decline with `no_capacity`.

**Submit.** Validate complete immutable launches and distinct batch IDs before dispatch. Match a fitting base and slot; use its actual fixed resources. Reject malformed quantities, identities, selectors and empty leases. Decline unsupported runtime caps, start-before deadlines, scratch reservations and unmatched environments/capabilities before side effects. Past deadlines are rejected. Never claim replacement work.

Construct `c2j run with-lease --jobdb … --job-id … --lease-file - --ci --input-mode fail`. Pass the exact opaque lease through stdin, never argv/environment/logs/listings. Pass actual CPU, memory, platform, pinned image/digest and verified capability facts using c2j's supported flags. Pass the resolved concrete base with `--execution-base`; retain `PULSE_BASE` only as diagnostic context. Use a guest c2j version compatible with JobDB v2 leases. Resolve selections to a commit for preparation, failing on lookup errors. Job startup invokes installed tools without installation or release lookup. The lease authorizes c2j to retrieve secrets; the provider receives no job secrets. Preserve LaunchID and full JobRef in durable/native metadata and listings.

**Admission and recovery.** Fsync a keyed request/native fingerprint and slot reservation before native creation. Identical launch IDs return their existing outcome; conflicting assignments are rejected. Accepted means the Orchard create response or local detached Tart dispatch succeeded; boot/delivery/execution may still fail. Lost responses remain `unknown`, including after absence in inventory. Never retry ambiguous clone/run operations. Observed matching native identity may resolve uncertainty. Keep terminal history for the owner scope's lifetime. Version 3 journals reject legacy state rather than resetting it.

**Backend execution.** Orchard uses REST startup scripts, events and power-state updates; labels select workers and must not carry arbitrary correlation fields. Direct Tart uses literal CLI arguments, preserves suspended-clone hardware, checks active MAC collisions, and detaches `tart run --no-graphics --suspendable`. Bind direct job ownership to a private UID marker, directory identity and hardware. Published source directories are replaceable; validate their required hardware and state without requiring the old directory/MAC identity. SSH delivers scripts through stdin. Persist private delivery data so host restart can retry idempotent delivery without repeating native launch. Closing the library never kills native jobs.

**Guest lifetime.** Root launchd owns bootstrap/delivery independent of the SSH session. Execute c2j once as the unprivileged worker account after durably recording intent. Bound setup and missing-delivery time, never the runtime of a zero-timeout worker. Shut down after c2j exits. Environment preparation is reusable only in unused image builders; never sanitize an executed VM for another job.

**Reconciliation and listing.** `Run`/`Reconcile` manage lifecycle. `List` is read-only, paginated, scoped, and excludes templates/terminal work. Preserve JobRef and LaunchID; expose no lease. Observation failure is an error, not an empty successful inventory. `Slots` and `Images` expose operational state only. Configuration changes and `Drain` retire idle slot reservations while preserving unresolved jobs and published sources. `PurgeImages` explicitly removes known sources after draining and completing all jobs; unregistered aliases are outside its scope. Missing known unused templates may be rebuilt; ambiguous creates remain reserved; failed builds are retained for inspection.

**Cleanup.** Never infer worker absence from age, failed status alone, or unreachable SSH. Require a native stopped observation. Recheck exact name, UID and immutable specification before deletion; quarantine mismatches. Direct Tart additionally validates local directory ownership. Finish when the owned native API/local record is absent; no additional physical-removal proof is required. Never prune by prefix or delete unrelated VMs.

**Security and testing.** Private state directories, atomic fsynced journals, sanitized errors, no redirects, verified controller TLS and explicit insecure lab HTTP. Lease-bearing native delivery records remain private. Optional direct SSH host-key pinning; otherwise trust the managed guest endpoint. Deterministic tests cover API validation, resource/base resolution, c2j invocation, duplicates, unknown dispatches, concurrent reservations, recovery, read-only listing, template identity, cleanup and HTTP/SSH process boundaries. Live tests cover two-slot preparation/resume, host-library reopen, reuse, and real JobDB execution through the public Submit API. A disposable fixture requires `macos-*arm64` and validates JobDB v2 lease execution, Nix execution, lease-bound secret retrieval, renewal beyond the initial lifetime, completion, and completed/expired lease rejection without reacquisition. The full-suite script fails on skipped/missing live assertions and saves redacted, Git-ignored reports before cleanup. Direct Tart live tests run on macOS and additionally update sources while an old clone runs, verify old/new identities, and execute jobs from the replacements.
